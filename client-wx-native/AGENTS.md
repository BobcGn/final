# WeChat Native Client Agent Rules

- 使用微信官方推荐的原生小程序开发方式、UI、生命周期与 API。
- 本工程是实验 baseline，不依赖 KMP 内部实现。
- 不为了与 KMP 保持代码结构一致而人为改变微信原生工程。
- 后续两套客户端应实现相同业务能力，并接受相同验收场景。
- 保留微信原生方案真实的开发成本和工程特征，否则对照数据无效。
- 仅通过已确认的 Backend API、协议和需求事实与其他模块协作。
- 原示例页已移除；现有四个业务页面（monitor/trends/alerts/settings）为正式实现，新增或改动必须同步 README、接口文档与测试。
- 两套客户端共同遵守 `../docs/api/openapi.yaml`，不得各自发明字段、告警等级或阈值单位。
- 目标能力包括实时仪表盘、温湿度/气体趋势、阈值滑块和历史告警；四个业务页面已实现，趋势曲线已有实现和单元测试。
- 负责微信原生端的成员/Agent 必须依照根规则使用 `multica` CLI，同步页面/组件、微信 API、接口联调、开发者工具验证和阻塞。
- 微信原生端修改遵守根 Git/PR 流程，分支使用 `feat/wx-...`、`fix/wx-...` 等完整名称；PR 应附微信开发者工具及真机验证状态。

## Documentation, Comments, and Tests

- 公共工具、服务模块、组件属性/事件和复杂数据转换必须使用 JSDoc；页面生命周期、微信 API 限制、权限和兼容分支必须说明原因与适用基础库版本。
- WXML/WXSS 的非显然交互、无障碍约束和平台 workaround 需要注释；不得为直观布局添加噪声注释。
- 页面、路由、API 模型、权限或基础库要求变化必须同步更新 `README.md` 和相关接口文档。
- 纯 JavaScript 业务逻辑必须有单元测试；页面/组件、网络请求、缓存、WebSocket 和阈值交互必须有组件或集成测试。
- 可测试 JavaScript 业务逻辑行覆盖率至少 80%，新增/修改核心逻辑目标至少 90%；告警展示、请求失败、重连、重复提交和设备确认超时必须覆盖。
- 微信开发者工具模拟器不能替代全部真机验证。涉及授权、网络、后台切换或设备兼容时，PR 必须记录基础库、工具版本、机型和结果。
- PR 必须报告语法/静态检查、单元测试、覆盖率、开发者工具构建和必要的真机集成结果。
